Book a court, find a match, pay from the app.

01 · The brief

Venues, matches and payments in one app.

Sports facilities in Pakistan ran on phone calls, WhatsApp and paper ledgers, with double bookings and untracked cash. Sportefy gives players venue discovery, booking, matches and a wallet in one app, and gives venue operators and platform staff a dashboard to run it, all on one versioned API that older app installs keep working against.

  • Players: find venues, book slots, pay from a wallet or at the venue, join matches and check in with a QR scan
  • Venue operators: facilities, operating hours, slot pricing, staff access and walk-in bookings
  • Platform staff: reporting, payment checks, promo codes, memberships and an audit trail
  • Realtime match chat and notifications on Supabase Realtime with row-level security

Key decisions

  1. 01An additive-only /v1 contract with one response envelope, so app versions already on phones keep working through every release
  2. 02Server-driven version gating: the API tells each app build whether to show a soft or a hard update prompt
  3. 03OpenAPI drift checks in CI: the spec must match the code before the admin client is regenerated from it
  4. 04One permission matrix in a shared package feeds both the API guards and the dashboard

What I worked on.

Flutter app

  • 21 feature modules, 823 passing tests, BLoC with clean architecture; offline request queue with replay, automatic token refresh, fault-tolerant parsing.
